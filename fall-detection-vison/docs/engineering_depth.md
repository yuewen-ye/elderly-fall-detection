# 老年人跌倒检测系统 — 工程深度与展示深度说明

## 一、工程深度

### 1.1 时序动作状态机（核心创新）

**问题**：原始系统仅靠"角度>45° 或 宽高比>1.4"单帧判断，弯腰捡东西、蹲下系鞋带会被误判为跌倒。

**解决**：引入六态时序状态机，每人独立运行：

```
UPRIGHT → BENDING → SITTING → FALLING → FALLEN → RECOVERED
```

每个状态绑定不同的特征组合条件：

| 状态 | 判定条件 | 语义 |
|---|---|---|
| FALLEN | AR > 1.4 AND CoG > 0.65 | 人体水平且贴近地面 |
| FALLING | v > 0.04 AND (AR > 0.9 OR CoG > 0.6) | 快速下降中 |
| SITTING | AR > 1.0 AND CoG > 0.55 AND |v| < 0.03 | 宽体、中等高度、静止 |
| BENDING | angle > 0.15 | 躯干倾斜但未倒地 |
| UPRIGHT | 默认 | 正常站立/行走 |

**时序平滑**：状态切换需连续 N 帧（默认 3）一致才确认，消除单帧噪声闪烁。

**误报抑制效果**：弯腰动作（AR≈0.6、CoG≈0.5、低速度）被正确分类为 BENDING，不触发 FALLING/FALLEN 警报。

### 1.2 分级预警链路

单一级别的"跌倒报警"无法区分紧急程度。系统实现三级递进：

| 级别 | 触发条件 | 含义 |
|---|---|---|
| WARNING | FALLING 状态（正在跌倒） | 疑似，需关注 |
| CRITICAL | FALLEN 状态（已倒地） | 确认跌倒 |
| EMERGENCY | FALLEN 持续 > 30s 未恢复 | 可能昏迷，需人工介入 |

预警级别通过 `AlertManager` 自动升级，超时未恢复从 CRITICAL → EMERGENCY。

### 1.3 可解释性输出

每次状态切换记录完整决策依据：

```json
{
  "track_id": 1,
  "from": "upright",
  "to": "fallen",
  "frame": 127,
  "reason": "FALLEN: angle=0° | AR=1.98 | CoG=0.90 | v=-0.002",
  "features": {
    "body_angle": 0.0,
    "aspect_ratio": 1.98,
    "cog_height": 0.90,
    "vertical_velocity": -0.002
  }
}
```

非技术人员（社区管理者、护理人员）能直接理解"为什么判定为跌倒"。

### 1.4 事件持久化

使用 SQLite 存储所有检测事件和警报记录：

- `events` 表：状态转换（track_id、状态、置信度、帧号、特征快照、触发原因）
- `alerts` 表：警报记录（级别、时间、消息、确认状态）

数据在重启后不丢失，支持事后审计和统计分析。

### 1.5 配置化 + 多人隔离

- 所有阈值（角度、宽高比、超时时间）从 `configs/system.yaml` 读取，无需改代码
- `StateMachineManager` 按 track_id 为每人维护独立状态机，多人同时活动互不干扰
- BoT-SORT 提供 Re-ID 能力，人员被短暂遮挡后恢复跟踪

### 1.6 系统可靠性

- 分级日志（检测日志 + 事件日志 + 系统日志）
- 优雅降级（模型加载失败提示、异常帧跳过）
- Flask REST API 支持第三方集成（呼叫系统、物业平台）

## 二、展示深度

### 2.1 专业监控 Dashboard

替换 Gradio 默认模板，构建深色安保监控风格界面：

| 区域 | 功能 |
|---|---|
| 顶部状态栏 | 系统在线指示灯 + 警报计数 |
| 左侧面板 | 图片/视频上传区 + 四格统计卡片（总事件/跌倒/危急/紧急） |
| 中央主画面 | 标注结果（骨架叠加 + 状态流转详情） |
| 右侧面板 | 事件时间线（彩色状态标签 + 特征数值） |

### 2.2 状态流转可视化

视频检测结果不只是"检出跌倒"，而是展示完整的状态变化链：

```
Track 1: upright → bending → upright → fallen @frame 127
```

每步转换带颜色编码（绿色→黄色→红色），答辩时能清楚展示"系统如何逐步判断跌倒"。

### 2.3 警报交互闭环

1. 检测到跌倒 → 红色警报横幅弹出（区分 WARNING/CRITICAL/EMERGENCY）
2. 操作员点击「确认」→ 横幅关闭 → 警报标记为已处理（写入数据库）
3. 这构成了一个完整的"检测 → 告警 → 响应"闭环，而非只有单向通知

| 步骤 | 操作 | 展示效果 |

### 2.6 与申报书创新点的对应

| 申报书创新点 | 系统实现 |

| 预训练模型 + 可解释规则特征 | LSTM + 状态机双通道，输出触发原因 |
| 多特征融合降低误判 | 5 维特征 + 时序平滑 + 状态机消除弯腰误报 |
| 面向社区真实场景 | 分级预警 + 事件管理 + 确认响应闭环 |
| 技术开发 + 社区调研闭环 | REST API 可对接社区平台，Dashboard 供管理者使用 |
